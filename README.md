# 運行管理ツール

| スクリプト | 用途 |
|---|---|
| `scripts/haisha_nippo.py` | 配車入力から**配車日報（実績帳票）**を作る |
| `scripts/etc_allocate_by_vehicle.py` | ETC利用明細PDFを解析し、**車番ごとに高速料金**を振り分ける |

どちらも **車番** をキーにしているので、日々の配車日報と月次の高速料金を
同じ車番で突き合わせできます。

# 配車日報

得意先から届く配送依頼を1つの入力シートにまとめ、当日の配車日報を出力します。
帳票は実際に使っている用紙と同じ**左右2ブロック**構成です。

- 左ブロック … **1便目**
- 右ブロック … **2便目以降**（2便目が1行目、3便目が2行目）
- 1乗務員＝1ブロック。行の並び順は『乗務員マスタ』の順

## 使い方

```
python scripts/haisha_nippo.py --template            入力ブック 配車入力.xlsx を作る
python scripts/haisha_nippo.py --tanto 藁科          入力にある日付ぶんの日報を作る
python scripts/haisha_nippo.py --date 2026-09-10 --tanto 藁科
```

主なオプション: `--input`（入力ブック）、`--outdir`（出力先）、
`--tanto`（右上の担当者名）、`--spacer`（乗務員ごとに空行を入れる）。

## 入力ブック `配車入力.xlsx`

| シート | 内容 |
|---|---|
| `配車入力` | 1行＝1便。**黄色の5列だけ**打ち込む |
| `乗務員マスタ` | 乗務員名。**この並び順が日報の行順になる** |
| `車番マスタ` | 車番→乗務員。車番を打つと乗務員が決まる |
| `得意先マスタ` | 得意先の一覧。プルダウンの元になる |
| `記入例` | 書き方の見本（日報には反映されない） |

`配車入力` の列は次の順です。

```
日付 | 車番 積荷 得意先 発地 着地 | 乗務員 便 備考
       ^^^^^^^^^^^^^^^^^^^^^^^^ ここだけ打つ（B〜F列・黄色）
```

打鍵を減らすため、空欄は次のように補います。**明示的に書けばそちらが優先**です。

| 欄 | 空欄のときの扱い |
|---|---|
| `日付` | 直前の行から引き継ぐ。1日分なら**先頭行に1回**書けばよい |
| `乗務員` | `車番マスタ` から引く。代車の日だけ手で書く |
| `便` | 同じ乗務員の中で上から順に1便目・2便目… |

- `車番` と `得意先` はマスタを参照する**プルダウン**です。
- **車番は便ごとに持ちます。** 同じ乗務員でも便で車を替えるため
  （例: 仲林 1464→2403、木村 9480→1983）、乗務員固定にはしていません。
- **車番を空欄にすると「未配車」** として日報の最後に赤く出ます。配車漏れの確認用です。
- コンテナ便のように車番欄へ `40ft`、積荷欄へ時刻を書く運用もそのまま通ります。
  この場合は車番マスタに無いので、乗務員欄だけ手で入れてください。

## 出力ブック `配車日報_YYYYMMDD.xlsx`

| シート | 内容 |
|---|---|
| `配車日報` | 用紙と同じ左右2ブロックの帳票。A4横1ページに収まるよう設定済み |
| `乗務員別集計` | 乗務員ごとの便数・使用車番・積荷・得意先 |
| `得意先別集計` | 得意先ごとの便数と担当乗務員（便数の多い順） |

日付は `令和 8年　9月　10日　（木）` の和暦で入ります。

## 手書き用紙との違い

用紙では乗務員が1便だけのとき、空いた右ブロックに**別の乗務員を詰めて**
書くことがあります（神長さん・小堀内さんなど）。本スクリプトは
1乗務員＝1ブロックで並べるため、その詰め込みは再現しません。
行数は同じ（2026/9/10 実績で28行）で、A4横1ページに収まります。

## FAXの取り込みについて

現状はFAXが紙で出力されるため、`配車入力` シートへの入力は手作業です。
自動化するには次の順で進めます。

1. **複合機のFAX受信を「紙出力」から「PDF保存／メール転送」に変更する。**
   設定変更だけで済むことが多く、ここが自動化の前提になります。
2. 得意先ごとの様式に合わせて読み取り位置を定義し、PDFから
   `配車入力` シートの列に流し込む（システム印字なので位置は毎回同じ）。
   例: 大晴通商の依頼書は `作業日時→日付` `品目→積荷` `配送先→着地`。
3. 読み取り結果を見ながら乗務員と車番を決め、本スクリプトで日報を出力する。

`配車入力` シートを入口として固定してあるため、2 が入っても
日報側のスクリプトはそのまま使えます。

# ETC利用明細 車番別 金額振り分け

ETC利用照会サービスの「ご利用明細書」PDFを解析し、車両番号ごとに通行料金を
集計して `高速料金` シートのC列に振り分けます。

## 使い方

```
python scripts/etc_allocate_by_vehicle.py
```

スクリプト先頭の `PDF` / `XLSX` / `OUT` のパスを対象ファイルに合わせて変更してください。

## 出力シート

| シート | 内容 |
|---|---|
| `高速料金` | 車番（担当者）ごとの集計。C列＝金額、D列＝振替の備考 |
| `車番別明細` | 車番ごとの利用明細1件1行。日付・時刻・入口/出口ＩＣ・通行料金・割引種別、車番ごとの小計付き |

件数は出力しません。

`車番別明細` の備考欄には、単独課金（本線料金所などの均一区間）と、
乗り替わりで別の車番に乗った明細（`実車番○○ に乗車`）が表示されます。

## 明細PDFのレコード構造

1レコードは3行で構成されます。

```
利用年月日(自) 利用年月日(至) (割引前料金) 車種   備考
時分(自)       時分(至)       (ETC割引額)  車両番号
利用IC(自)     利用IC(至)     通行料金     ETCカード番号
```

- 割引が無いレコードでは `(割引前料金)` `(ETC割引額)` が出力されません。
- 本線料金所（日光本線料金所・大沢本線料金所など）の単独課金レコードは
  日付・時刻が1つしか出力されないため、時刻行の判定は「1つまたは2つ」を許容します。
- 集計対象は割引適用後の **通行料金**（3行目）です。

## 乗り替わりの付け替え

代車・乗り替わりでドライバーが入れ替わった日は、スクリプト冒頭の `OVERRIDES` に
`(実際に走った車番, 利用日)` → `料金を負担する車番` を登録すると、その日の明細だけが
付け替えられ、E列に備考が入ります。

```python
OVERRIDES = {
    (46, '26/08/20'): 9283,   # 8/20・8/21は車番46に伊垣さん(9283)が乗車
    (46, '26/08/21'): 9283,
}
```

判定は利用開始日（利用年月日(自)）基準です。

## 検証

集計値の合計が明細書1枚目の「通行料金合計」と一致することを確認しています。

- 通行料金合計: ￥4,937,200（PDF記載の合計と一致）

付け替えは車番間の移動のみで総額は変わらないため、付け替え後も合計は一致します。
